# 🎤 多 Agent 辩论系统

基于 LangGraph 的多智能体辩论系统，支持完整辩论赛流程：**立论 → 攻辩（多轮循环）→ 自我反思 → 驳论 → 总结陈词 → 评委评分**。

## ✨ 核心特性

- **多 Agent 协作**：正方/反方/评委各有独立 Agent，角色分工明确
- **五层立场防御机制**：立场铁律提示词 + 明确立场表述 + 攻辩/驳论策略指导 + 反思防反噬约束 + 评委立场坚定性评分，系统性解决大模型中立摇摆、中途倒戈问题
- **Self-Reflection 自我反思机制**（核心算法亮点）：每轮攻辩后，双方 Agent 批判自己之前的论证，找出漏洞并在下一轮修正
- **多轮攻辩循环**：基于 LangGraph 条件边实现循环，可配置 1-5 轮
- **专业评委评分**：8 个维度独立打分（含立场坚定性），输出胜负和专业点评
- **实时演示界面**：Gradio 界面，辩论过程实时展示
- **模型无关**：统一封装 OpenAI 兼容接口，支持 DeepSeek / OpenAI / 智谱 GLM 等模型
- **V2 RAG 论据检索**：支持加载自定义论据文档，辩论时自动检索相关论据注入 prompt，立场隔离（正方只检索正方论据，反方只检索反方论据），基于 FAISS 向量检索
- **V3 Tavily 联网检索**：辩论时实时联网搜索最新论据，立场感知搜索（正方搜支持正方的内容，反方搜支持反方的内容），攻辩时用对方论点做查询搜索反驳素材

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 API Key

复制 `.env.example` 为 `.env`，填入你的 API Key：

```bash
# 推荐用 DeepSeek（免费额度够开发）
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-chat
```

> 也支持 OpenAI / Qwen 等所有兼容 OpenAI 接口的模型。

### 3. 运行界面

```bash
python app.py
```

然后浏览器打开 `http://localhost:7860`

### 4. 命令行运行（无界面）

```python
from debate_agent import run_debate, format_debate_result

state = run_debate(
    topic="猫和狗谁更适合当宠物？",
    max_rounds=3,
    reflection_enabled=True,
    affirmative_stance="猫比狗更适合当宠物",   # 建议明确指定双方立场，防止立场跑偏
    negative_stance="狗比猫更适合当宠物",
)

print(format_debate_result(state))
```

> 提示：对于"选择题"辩题（如"猫和狗谁更适合当宠物"）或带贬义倾向的辩题（如"年轻人应不应该躺平"），务必传入 `affirmative_stance` / `negative_stance` 明确双方立场，否则模型可能自行脑补导致立场混淆。

### 5. V2 RAG 论据检索（可选）

开启 RAG 后，辩手 Agent 会在立论/攻辩/驳论前从你提供的论据文档中检索相关论据，注入 prompt，让辩论引用真实数据而非凭空编造。

**准备论据文档**：将正方/反方论据分别写成 `.md` 或 `.txt` 文件，放在 `data/` 目录下（项目已附带猫/狗示例论据）。

**命令行开启 RAG**：

```python
from debate_agent import run_debate

state = run_debate(
    topic="猫和狗谁更适合当宠物",
    max_rounds=2,
    reflection_enabled=True,
    affirmative_stance="猫更适合当宠物",
    negative_stance="狗更适合当宠物",
    rag_enabled=True,                                    # 开启RAG
    affirmative_evidence_files=["data/affirmative_evidence_cat.md"],  # 正方论据
    negative_evidence_files=["data/negative_evidence_dog.md"],        # 反方论据
)
```

**Gradio 界面开启 RAG**：勾选"启用 RAG 论据检索"，在展开的输入框中填入正方/反方论据文件路径（多个用逗号分隔）。

**Embedding 配置**：RAG 需要 embedding API。系统会自动复用你在 `.env` 中配置的 LLM API（智谱 GLM 自动用 `embedding-2` 模型，OpenAI 自动用 `text-embedding-3-small`）。也可以单独配置：

```bash
EMBEDDING_API_KEY=your_key
EMBEDDING_BASE_URL=https://open.bigmodel.cn/api/paas/v4/
EMBEDDING_MODEL=embedding-2
```

**立场隔离**：正方论据库和反方论据库完全分开，正方 Agent 只会检索正方论据，反方 Agent 只会检索反方论据，不会出现"正方引用反方论据"的情况。

### 6. V3 Tavily 联网检索（可选）

开启联网检索后，辩手 Agent 会在每次发言前用 Tavily 实时搜索支持己方立场的最新论据，不需要自己准备论据文档。

**配置 Tavily API Key**：在 [tavily.com](https://tavily.com) 免费注册（每月 1000 次免费搜索），获取 API Key，填入 `.env`：

```bash
TAVILY_API_KEY=tvly-xxxxxxxxxxxxxxxx
```

**命令行开启联网检索**：

```python
state = run_debate(
    topic="猫和狗谁更适合当宠物",
    max_rounds=2,
    web_search_enabled=True,
)
```

**Gradio 界面**：勾选"启用 Tavily 联网检索"即可。

> 注意：联网检索会增加辩论时间（每次发言前多一次搜索调用）。V2 离线检索和 V3 联网检索可以同时开启，两者论据都会注入 prompt。

## 🧠 核心算法说明

### Self-Reflection 自我反思机制

每轮攻辩结束后，双方 Agent 会暂停辩论，进行内部反思：

1. **回顾自己的所有发言**，找出逻辑漏洞和论据缺陷
2. **分析对方的所有发言**，找出自己还没有效回应的观点
3. **生成反思笔记**（仅自己可见，对方不知道）
4. **下一轮攻辩时**，将反思笔记作为输入，修正自己的论证

这个机制模拟了人类辩手在辩论间隙的复盘和策略调整，显著提升了多轮辩论的质量和深度。

### LangGraph 图编排

使用 LangGraph 的图结构（而非线性 Chain）实现辩论流程，核心优势：

- **循环支持**：攻辩阶段需要多轮循环，图结构天然支持
- **条件边**：根据当前轮数判断是继续攻辩还是进入驳论
- **状态共享**：所有 Agent 共享同一个 state dict，辩论历史完整保留
- **可观测性**：每个节点执行完都可以获取中间状态，便于调试和展示

### V2 RAG 论据检索机制

RAG（Retrieval-Augmented Generation，检索增强生成）让辩手 Agent 不再凭空编造数据，而是从你提供的论据文档中检索真实论据。

**工作流程**：

1. **文档加载与切分**：加载 `.md`/`.txt` 论据文档，按段落切分为文本块（超过 500 字的段落再按句子切分）
2. **向量化**：调用 embedding API 将每个文本块转为向量（智谱 `embedding-2` 维度 1024）
3. **构建 FAISS 索引**：用 FAISS IndexFlatL2 存储向量，支持高效相似度检索
4. **辩论时检索**：辩手 Agent 在立论/攻辩/驳论前，用"辩题+对方上轮论点"作为查询，从己方论据库中检索 Top-3 最相关论据
5. **注入 Prompt**：检索到的论据格式化为"【可引用的论据】"块，拼接到 prompt 末尾，引导模型引用

**立场隔离设计**：正方和反方各有独立的知识库实例和 FAISS 索引，正方 Agent 只能访问正方论据库，反方只能访问反方论据库，从物理上杜绝立场混淆。

### V3 Tavily 联网检索机制

开启联网检索后，辩手 Agent 在每次发言前用 Tavily 实时搜索支持己方立场的最新论据。

**工作流程**：

1. **立场感知查询构造**：立论时搜索"己方立场表述 + 优点/数据/研究"；攻辩时搜索"己方立场 + 反驳 + 对方论点关键词"，专门找反驳素材
2. **Tavily 搜索**：调用 Tavily API（专门为 AI Agent 设计的搜索 API，返回干净的正文摘要，无需额外解析网页）
3. **结果格式化**：搜索结果格式化为"【联网检索到的可用论据】"块，包含标题、来源URL、内容摘要
4. **注入 Prompt**：拼接到 prompt 末尾，引导模型引用搜索结果中的数据和研究

**与 V2 RAG 的关系**：V2 离线检索和 V3 联网检索可以同时开启，两者的论据都会注入 prompt，模型可以综合使用。离线检索适合你已经有明确论据文档的场景，联网检索适合需要最新信息或不想手动准备论据的场景。

## 📊 评测维度

评委从以下 8 个维度对双方独立打分（0-10 分）：

1. **立论深度**：论点是否有深度，定义和标准是否清晰
2. **逻辑论证**：推理是否严密，有无逻辑漏洞
3. **论据质量**：数据、案例、类比是否有力且相关
4. **反驳能力**：是否精准抓住对方漏洞并有效反驳
5. **应变能力**：面对对方攻击是否能灵活应对
6. **语言表达**：语言是否流畅、有说服力
7. **整体配合**：各阶段发言是否形成完整体系
8. **立场坚定性**：是否始终坚持己方立场，有无动摇、妥协或认同对方观点的情况

## 🛠️ 技术栈

- **LangGraph** — 多 Agent 工作流编排
- **LangChain** — LLM 应用框架
- **OpenAI SDK** — 统一 LLM 调用（兼容 DeepSeek / 智谱 GLM / GPT）
- **FAISS** — 向量检索库（V2 RAG 论据检索）
- **Tavily** — 专为 AI Agent 设计的搜索 API（V3 联网检索）
- **Gradio** — 快速构建演示界面
