# 🧠 多 Agent 决策助手

基于 LangGraph 的多智能体决策辅助系统。输入任何你纠结的决策问题，AI 自动生成正反方立场，进行多轮攻防分析，最后给出综合评估。

**适用场景**：职业选择、购房购车、留学考研、跳槽转行、投资决策等任何需要权衡利弊的决策。

## ✨ 核心特性

- **多 Agent 对抗分析**：支持方/反对方/评估方各有独立 Agent，角色分工明确
- **五层立场防御机制**：立场铁律提示词 + 明确立场表述 + 攻防策略指导 + 反思防反噬约束 + 立场坚定性评估，系统性解决大模型中立摇摆、中途倒戈问题
- **Self-Reflection 自我反思机制**（核心算法亮点）：每轮分析后，双方 Agent 批判自己之前的论证，找出漏洞并在下一轮修正
- **多轮攻防循环**：基于 LangGraph 条件边实现循环，可配置 1-5 轮
- **综合决策评估**：8 个维度独立打分（含立场坚定性），输出评估结果和专业点评
- **实时演示界面**：Gradio 界面，分析过程实时展示，支持示例问题一键填充
- **模型无关**：统一封装 OpenAI 兼容接口，支持智谱 GLM / DeepSeek / OpenAI 等模型
- **V2 RAG 论据检索**：支持加载自定义论据文档，分析时自动检索相关论据注入 prompt，立场隔离（支持方只检索支持方论据，反对方只检索反对方论据），基于 FAISS 向量检索
- **V3 Tavily 联网检索**：分析时实时联网搜索最新论据，立场感知搜索（支持方搜支持己方的内容，反对方搜支持己方的内容），攻防时用对方论点做查询搜索反驳素材

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 API Key

复制 `.env.example` 为 `.env`，填入你的 API Key：

```bash
# 智谱 GLM（推荐，国内访问稳定）
ZHIPU_API_KEY=your_api_key
ZHIPU_BASE_URL=https://open.bigmodel.cn/api/paas/v4
ZHIPU_MODEL=glm-4-flash
```

> 也支持 DeepSeek / OpenAI / Qwen 等所有兼容 OpenAI 接口的模型。

### 3. 运行界面

```bash
python app.py
```

然后浏览器打开 `http://localhost:7860`

界面提供 4 个示例问题快捷按钮：要不要考公？这套房该不该买？要不要转行做算法？要不要读研？点击即可一键填充。

### 4. 命令行运行（无界面）

```python
from debate_agent import run_debate, format_debate_result

state = run_debate(
    topic="要不要考公？",
    max_rounds=3,
    reflection_enabled=True,
    affirmative_stance="应该考公",   # 建议明确指定双方立场，防止立场跑偏
    negative_stance="不应该考公",
)

print(format_debate_result(state))
```

> 提示：对于带贬义倾向的决策问题（如"要不要躺平"）或模型容易中立的问题，务必传入 `affirmative_stance` / `negative_stance` 明确双方立场，否则模型可能自行脑补导致立场混淆。

### 5. V2 RAG 论据检索（可选）

开启 RAG 后，分析 Agent 会在立论/攻防/反驳前从你提供的论据文档中检索相关论据，注入 prompt，让分析引用真实数据而非凭空编造。

**准备论据文档**：将支持方/反对方论据分别写成 `.md` 或 `.txt` 文件，放在 `data/` 目录下。

**命令行开启 RAG**：

```python
from debate_agent import run_debate

state = run_debate(
    topic="要不要考公？",
    max_rounds=2,
    reflection_enabled=True,
    affirmative_stance="应该考公",
    negative_stance="不应该考公",
    rag_enabled=True,                                    # 开启RAG
    affirmative_evidence_files=["data/affirmative_evidence.md"],  # 支持方论据
    negative_evidence_files=["data/negative_evidence.md"],        # 反对方论据
)
```

**Gradio 界面开启 RAG**：勾选"离线论据检索（RAG）"，在展开的文件上传区域上传支持方/反对方论据文件。

**Embedding 配置**：RAG 需要 embedding API。系统会自动复用你在 `.env` 中配置的 LLM API（智谱 GLM 自动用 `embedding-2` 模型，OpenAI 自动用 `text-embedding-3-small`）。也可以单独配置：

```bash
EMBEDDING_API_KEY=your_key
EMBEDDING_BASE_URL=https://open.bigmodel.cn/api/paas/v4/
EMBEDDING_MODEL=embedding-2
```

**立场隔离**：支持方论据库和反对方论据库完全分开，支持方 Agent 只会检索支持方论据，反对方 Agent 只会检索反对方论据，不会出现"支持方引用反对方论据"的情况。

### 6. V3 Tavily 联网检索（可选）

开启联网检索后，分析 Agent 会在每次发言前用 Tavily 实时搜索支持己方立场的最新论据，不需要自己准备论据文档。

**配置 Tavily API Key**：在 [tavily.com](https://tavily.com) 免费注册（每月 1000 次免费搜索），获取 API Key，填入 `.env`：

```bash
TAVILY_API_KEY=tvly-xxxxxxxxxxxxxxxx
```

**命令行开启联网检索**：

```python
state = run_debate(
    topic="要不要考公？",
    max_rounds=2,
    web_search_enabled=True,
)
```

**Gradio 界面**：勾选"联网检索（Tavily）"即可。

> 注意：联网检索会增加分析时间（每次发言前多一次搜索调用）。V2 离线检索和 V3 联网检索可以同时开启，两者论据都会注入 prompt。

## 🧠 核心算法说明

### Self-Reflection 自我反思机制

每轮攻防结束后，双方 Agent 会暂停分析，进行内部反思：

1. **回顾自己的所有发言**，找出逻辑漏洞和论据缺陷
2. **分析对方的所有发言**，找出自己还没有效回应的观点
3. **生成反思笔记**（仅自己可见，对方不知道）
4. **下一轮攻防时**，将反思笔记作为输入，修正自己的论证

这个机制模拟了人类在决策过程中的复盘和策略调整，显著提升了多轮分析的质量和深度。

### LangGraph 图编排

使用 LangGraph 的图结构（而非线性 Chain）实现分析流程，核心优势：

- **循环支持**：攻防阶段需要多轮循环，图结构天然支持
- **条件边**：根据当前轮数判断是继续攻防还是进入反驳
- **状态共享**：所有 Agent 共享同一个 state dict，分析历史完整保留
- **可观测性**：每个节点执行完都可以获取中间状态，便于调试和展示

### V2 RAG 论据检索机制

RAG（Retrieval-Augmented Generation，检索增强生成）让分析 Agent 不再凭空编造数据，而是从你提供的论据文档中检索真实论据。

**工作流程**：

1. **文档加载与切分**：加载 `.md`/`.txt` 论据文档，按段落切分为文本块（超过 500 字的段落再按句子切分）
2. **向量化**：调用 embedding API 将每个文本块转为向量（智谱 `embedding-2` 维度 1024）
3. **构建 FAISS 索引**：用 FAISS IndexFlatL2 存储向量，支持高效相似度检索
4. **分析时检索**：分析 Agent 在立论/攻防/反驳前，用"决策问题+对方上轮论点"作为查询，从己方论据库中检索 Top-3 最相关论据
5. **注入 Prompt**：检索到的论据格式化为"【可引用的论据】"块，拼接到 prompt 末尾，引导模型引用

**立场隔离设计**：支持方和反对方各有独立的知识库实例和 FAISS 索引，支持方 Agent 只能访问支持方论据库，反对方只能访问反对方论据库，从物理上杜绝立场混淆。

### V3 Tavily 联网检索机制

开启联网检索后，分析 Agent 在每次发言前用 Tavily 实时搜索支持己方立场的最新论据。

**工作流程**：

1. **立场感知查询构造**：立论时搜索"己方立场表述 + 优点/数据/研究"；攻防时搜索"己方立场 + 反驳 + 对方论点关键词"，专门找反驳素材
2. **Tavily 搜索**：调用 Tavily API（专门为 AI Agent 设计的搜索 API，返回干净的正文摘要，无需额外解析网页）
3. **结果格式化**：搜索结果格式化为"【联网检索到的可用论据】"块，包含标题、来源URL、内容摘要
4. **注入 Prompt**：拼接到 prompt 末尾，引导模型引用搜索结果中的数据和研究

**与 V2 RAG 的关系**：V2 离线检索和 V3 联网检索可以同时开启，两者的论据都会注入 prompt，模型可以综合使用。离线检索适合你已经有明确论据文档的场景，联网检索适合需要最新信息或不想手动准备论据的场景。

## 📊 评估维度

评估方从以下 8 个维度对双方独立打分（0-10 分）：

1. **立论深度**：论点是否有深度，定义和标准是否清晰
2. **逻辑论证**：推理是否严密，有无逻辑漏洞
3. **论据质量**：数据、案例、类比是否有力且相关
4. **反驳能力**：是否精准抓住对方漏洞并有效反驳
5. **应变能力**：面对对方攻击是否能灵活应对
6. **语言表达**：语言是否流畅、有说服力
7. **整体配合**：各阶段发言是否形成完整体系
8. **立场坚定性**：是否始终坚持己方立场，有无动摇、妥协或认同对方观点的情况

## 🛠️ 技术栈

- **LangGraph** — 多 Agent 工作流编排
- **LangChain** — LLM 应用框架
- **OpenAI SDK** — 统一 LLM 调用（兼容智谱 GLM / DeepSeek / GPT）
- **FAISS** — 向量检索库（V2 RAG 论据检索）
- **Tavily** — 专为 AI Agent 设计的搜索 API（V3 联网检索）
- **Gradio** — 快速构建演示界面
